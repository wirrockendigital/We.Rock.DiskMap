Settings & operations

Settings and personal view

The gear opens Settings. Tabs separate appearance, scan options, version information and diagnostics.

Appearance, Scans and Info

  • Appearance: choose light or dark presentation and German or English.
  • Scans: set special categories for the next scan, toggle visibility, change the age threshold or reset the index.
  • Info: view the installed app version. It also appears at the bottom left of the main window.
  • Debug: optional session log and technical status.

Saving and scope

The compact display and scan options are applied through their controls. The age threshold applies to your account in this browser. Saved views and personal presentation do not change shared scan data or DSM permissions.

Settings & operations

Configuration and advanced administration

The compact main interface focuses on scope selection, scans and analysis. Advanced administration is separate from those everyday controls.

Configuration backups

The advanced administration area supports configuration export/import; those controls are not exposed in the current compact interface. A configuration export contains profiles and eligible settings, not complete scan indexes, passwords or file contents.

Import has a 4 MiB limit. Sources must be mapped to the target NAS; equal names do not prove identity. Imported profiles receive new IDs and do not start automatically. Use a consistent package-data backup if indexes also need to be preserved.

Settings & operations

Scheduled scans in DSM

Manual scans and the queue are available directly in the app. Recurring schedules are configured separately in DSM Task Scheduler.

Review existing tasks

Advanced profile management provides profile-specific invocation templates; it is not part of the current compact interface. Use only a template matching the installed package and exact profile. The app does not create a DSM schedule automatically.

Tasks reference profile IDs, not just names. Review existing DSM tasks after imports, profile removal, NAS migration or uninstalling. CLI protocol versions are not application versions.

Settings & operations

Updates and recovery

Install updates through the supported DSM package workflow. If a problem occurs, preserve the error and the installed package identity.

Update and recover a usable state

Package migration backs up control information before changes. A schema downgrade is not automatically reversible. Do not manually swap databases after an unsuccessful upgrade; use the documented administrative recovery procedure with the matching bundle.

Account for active scans before updating. A successful package start and visible existing result are separate checks from performing another complete scan of your shares.

Uninstall and reinstall

Review the package dialog’s choice to retain or remove app data. Analysed shares and source files are separate. After reinstalling or moving to another NAS, check package read permissions and sources again. User-created DSM tasks must be removed or adjusted separately.

Failed update

Preserve the package/build identity and verified bundle under upgrades/. Administrative recovery runs with the package stopped, under its service account, using the installed daemon, its canonical socket and --upgrade=restore. The displaced control state remains in the bundle. Startup remains blocked until a matching package or successful prepare/apply qualifies the version. Do not manually swap databases or assume automatic downgrade compatibility.

Backup and reinstall

Store configuration exports securely; they contain private names and paths but no complete indexes. Optional index backups require a consistent state with writes stopped. After import or moving to another NAS, explicitly map sources and check permissions. Imported profiles initially remain inactive; saving starts no scan.

Uninstall and remaining tasks

Export configuration before uninstalling and review whether to retain or remove app data in the package dialog. Separately review your DSM tasks by profile ID; imported or newly created profiles with the same name do not replace that ID. Explicitly remove obsolete tasks. Analysed shares are not deleted.
