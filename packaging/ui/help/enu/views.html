Maps & navigation

Maps and the folder tree

Disk Map and Radial use the same recorded snapshot. The presentation changes, not the underlying files.

Rectangles and rings

In Disk Map, rectangle area represents size. Radial uses rings for directory levels; angles represent size shares. Large files stand out quickly.

The map includes subfolders. A large file tile may therefore live deeper than the selected folder. Hover or select it to inspect its full path in the status bar and selection details.

Very large file counts

Millions of files cannot all be individually distinguishable on one screen. Dense views may contain detail groups. These are not single large files. Open the corresponding scope or use the file list and search to inspect individual entries.

Navigate and arrange the workspace

  1. Click a folder name to view it. The arrow beside it only expands or collapses its children.
  2. Use the breadcrumb at the top to go to ancestors. Clicking a folder in the map also changes scope.
  3. The tree toolbar sorts by name or size and changes direction. Natural alphanumeric name order is the default.
  4. Toggle sidebars with the header icons. Drag their separators to adjust width.

Keep your view

The selected view, sidebar widths, expanded paths and other display preferences are saved for your account. Switching tabs or focus should not start a scan. Recorded scans remain shared; personal display preferences do not create separate file-access permissions.

Maps & navigation

Open and manage files

The context menu connects analysis with DSM. Available actions depend on the entry and installed DSM applications.

Show in File Station

  1. Right-click a file in the map or a folder in the left tree.
  2. Choose Show in File Station. DSM opens the corresponding location. Partial coverage elsewhere does not automatically block a valid path.

Open and delete

Open uses a suitable DSM viewer when supported by the file and installed applications. File actions use the current DSM session and its permissions. A recorded scan does not prove the file still exists unchanged.

Delete file deletes a real source file and requires explicit confirmation. Check the full path before confirming. Delete index for this folder removes only DiskMap results, not NAS files.

Understand size values

Displayed sizes describe the recorded snapshot and chosen visibility. They are not a live measurement of free volume capacity.

Folder totals and hidden content

Folder sizes are derived from recorded files and descendants. The tree retains the last known size even when another folder is selected. A dash means unknown or not recorded; 0 B is a recorded zero size.

The number at the top right describes visible content. Include recycle bins or system content to include them in the display. The visible total can therefore be smaller than the entire recorded dataset.

File size is not physical usage

Logical file size can differ from physical Btrfs usage because of compression, sparse files or shared blocks. Maps do not precisely allocate every physical volume block. Snapshot estimates are displayed separately and are not added to the file map.
