Index & categories

Show recycle bins and system content

Recording and displaying are separate choices. You can keep special content in the index without always showing it in the map.

1 · Include in the next scan

Under Settings → Scans → Scan and include in index, choose recycle bins and system files/folders such as @eaDir, .DS_Store or .SMB files. Changes apply to the next scan. Existing results are not retroactively expanded.

2 · Show in the interface

Beside the size at the top right, the recycle-bin and system-files icons toggle their categories across the map, folder tree and file list. The same options appear under Settings → Scans → Show in maps and lists. Visible special content is rendered in grayscale.

The three icon states

  • Normal gray recycle bin: present on the share and readable by the app.
  • Red recycle-bin outline, no strike: present, but the app lacks read access.
  • Dimmed recycle bin with a red strike: not present on the share.
  • Unknown status is never displayed as an absent bin. The tooltip explains the state. Subfolders inherit their share’s status; NAS and volume views aggregate it.
  • Not indexed: showing/hiding remains disabled even when the bin exists and is readable. Presence and index inclusion are separate.
  • System files: dimmed means unavailable in the index; a red strike still indicates missing read access recorded by the last scan.

Snapshot storage report

Synology snapshots share blocks with current files and other snapshots. Their additional storage usage cannot therefore be represented correctly as ordinary file tiles.

View a report

  1. Select a share or a folder inside a share.
  2. Click the layers icon, Snapshot storage report, beside the category icons on the right.
  3. Read the estimate together with its period and calculation date. Even when viewing a subfolder, the report covers the whole share.

No report yet?

Create a report for the share in Snapshot Replication using Snapshot → Calculate Size. DiskMap reads a completed DSM report; opening it does not recalculate every snapshot block.

The #snapshot folder does not need to be visible in File Station. The report is independent of that visibility. Without a suitable completed report, no size is invented and zero is not presented as a measurement.

Keep the estimate separate

The estimate belongs to its stated period and may be older than your last file scan. It is not added to the file-map total and is not the exact size of one snapshot folder.

Delete and rebuild the index

The index is DiskMap’s recorded file catalogue. Deleting the index and deleting a file are different actions.

Reset one scope

  1. Right-click the relevant folder in the left tree.
  2. Choose Delete index for this folder and inspect the scope in the confirmation dialog.
  3. Confirm only the intended scope. Its results are then unavailable until you scan it again.

Reset the entire index

Settings → Scans contains Delete entire index. This also requires confirmation. Active scan jobs may block deletion. Source files are retained; recorded analysis results must be rebuilt afterwards.

Package data is separate from scanned files

DSM manages package data through SYNOPKG_PKGVAR. control.db holds control information, generations/ holds scan indexes, upgrades/ holds recovery bundles; run/control.sock and diskmapd.pid are runtime files. Do not edit or move them while the service is running.
