Access & troubleshooting

Setup and read permissions

A DSM administrator installs and uses the app. The scanner reads as the internal system user we-rock-diskmap, not automatically with the signed-in administrator’s full permissions.

Grant access to shared folders

  1. Open DSM → Control Panel → Shared Folder and select the required share.
  2. Open Edit → Permissions and select System internal user.
  3. Allow Read only for we-rock-diskmap and save. Repeat for the shares you want to analyse.
  4. Reopen DiskMap or use Check shared folders again on the setup screen. A newly discovered share appears without a full NAS scan; scan it separately when ready.

Check subfolder permissions

Read access at the share root does not guarantee access to every descendant. Separate ACLs, encrypted or unmounted scopes and protected recycle bins may prevent access. Check the relevant permissions in File Station. The app never expands permissions automatically.

Access & troubleshooting

Recycle bin and administrator restriction

An unreadable #recycle folder is not empty. The package account also needs suitable read permissions here. DSM’s administrator restriction and manually assigned recycle-bin permissions are linked.

Important: permissions change the checkbox

Adding we-rock-diskmap with read access to #recycle automatically clears DSM’s “Restrict access to administrators only” checkbox.

Checking that box again removes the app user’s access again. These two settings cannot therefore be combined independently as a lasting solution.

Option 1: assign explicit recycle-bin permissions

  1. In File Station, select #recycle in the required share.
  2. Open Properties → Permission and add the internal system user we-rock-diskmap.
  3. Allow read, list and traverse access for the folders and files to be scanned. Grant no write or delete access.
  4. After saving, check other accounts’ effective access too. Admin-only is now cleared; do not re-enable it if the app should keep read access.
  5. Repeat for other recycle bins and refresh the affected scan scope.

Option 2: clear the DSM administrator restriction

Under Control Panel → Shared Folder → Edit → General, clear the restriction for the enabled recycle bin. Then check effective permissions: other authorised users may gain access to deleted files. Clearing the checkbox is not a substitute for checking the package account’s read access.

After changing permissions

Recycle-bin status is checked briefly at the share’s #recycle directory when inventory loads, without a recursive scan. After changing permissions, reopen the app or refresh inventory. Use Refresh to update stored contents separately. Read access at the bin itself does not guarantee access to every descendant. Visibility switches do not change permissions.

Access & troubleshooting

Photo Station and Synology Photos

The photo share may retain custom subfolder permissions from Photo Station or an earlier setup. Access in the photo application and read access at the share root do not establish that the DiskMap package account can read every subfolder.

Why is most of my photo collection missing?

DiskMap scans as the internal system user we-rock-diskmap. A subfolder without read and traversal permission has an unknown size. Even a recent scan can therefore be incomplete. In the directory tree, the tooltip explains an incomplete size; an incomplete zero appears as — rather than an empty folder.

Check read access narrowly

DiskMap does not change these permissions automatically. A blanket reset of subfolder permissions or renaming the photo share is not required for this diagnosis.

Official instructions: Synology: ACL permissions for subfolders of photo.

  1. In DSM → Control Panel → Shared Folder → photo → Permissions, check Read only for the internal system user we-rock-diskmap.
  2. Also inspect the specific unreadable subfolders and their own ACLs. Add only package read and traversal access, retaining existing user and photo-application permissions.
  3. Synology Photos also manages Shared Space access inside the photo application. File Station changes do not automatically become photo-application permissions. Older Photo Station folders may restrict permission editing in File Station; consult the Synology instructions for the installed photo application.
  4. Scan the affected share again. Reloading the interface does not add missing index data.

Administrators and sessions

The app is restricted to DSM administrators. Personal interface preferences and shared scan data serve different purposes.

Which permissions apply?

Authorised administrators use shared scan data. The restricted package user we-rock-diskmap determines what the scanner can read. File Station actions additionally check your current DSM session’s permissions.

If the session expires, sign in to DSM again and reopen the app. This starts no new scan. Do not assume standard accounts can access private subsets: the app does not provide personal scan isolation for standard users.

Access & troubleshooting

Notifications and troubleshooting

The bell keeps relevant notifications. Diagnostics help investigate failures without cluttering normal use.

Read notifications

Important notices appear at the top right. Dismiss one with X and revisit it in the bell history. Age and progress are already shown in the interface, avoiding repeated cache notices.

Enable debug when needed

  1. Open Settings → Debug and enable logging before reproducing the issue. It is off by default.
  2. Choose All, Info, Warning, Error or Critical. The display shows the latest 500 matching entries.
  3. Adjust the size limit if needed: default 10 MB, range 1–100 MB. Oldest entries are removed at the limit.
  4. Export the filtered log before closing the app. The export includes all retained matches; disabling logging or closing the app clears the session log.

Quick troubleshooting

  • Share missing: check package read permissions and reload inventory; no full scan is needed.
  • Recycle bin looks empty: inspect permissions and the admin-only checkbox, then refresh the scope.
  • File missing on the right: inspect search text, type, files/folders and Include subfolders.
  • Map missing: select a recorded scope; inspect the queue and notifications.
  • Scan appears stuck: distinguish traversal from index preparation; preserve a timed debug log if the problem persists.

Share support information

Record app/package version, DSM version, time and reproduction steps. Logs are not sent automatically. Private paths require separate consent; inspect exports and screenshots before sharing. Never include credentials or session values in a support request.

No scan yet

Select NAS, volume, share or folder and explicitly start a scan. No snapshot does not mean an empty NAS.

No search results

Review the visible search and filter rules and reset them if needed. A bounded window without matches is not a complete search result.

Empty recorded folder

This folder contains no files in the snapshot. This is a historical observation; missing read access does not establish an empty folder.

Missing read permission

Check the affected scope under Permissions. In DSM, the package service needs read access to that share and its descendants. Do not grant blanket permissions.

Missing volume

Check in DSM whether the selected volume is available and mounted, then refresh the inventory. Missing data remains unknown rather than zero bytes.

Locked share

Unlock the share in DSM, then check the scope again. DiskMap does not request an encryption key.

New scan failed

Check scan status and local diagnostics. A previous usable complete snapshot remains separate from the failed job. Start another scan only explicitly.

Partial scan completed

Available partial results appear automatically. Review the coverage reasons. Unknown areas are not zero bytes; refresh the scope after resolving the cause.

Index storage full or below reserve

The job stops in a controlled way; a protected previous snapshot is retained. Check free space for the package data area in DSM. Do not manually delete database files. Explicitly start a new scan after resolving the issue.

File removed since scanning

The filename describes the recorded snapshot. If current target validation confirms an existing parent folder, File Station can open it after your confirmation. File selection is not guaranteed.

DSM session expired

Further data access is blocked. Use Sign in to DSM to authenticate again. Enter credentials only in DSM; local help remains readable.

Graphics unavailable

Use the object list and navigation for the same snapshot. A rendering failure is not an empty folder and does not require an automatic scan.

DSM function unavailable

Check the integration status of the affected function, such as File Station. An open request does not confirm the displayed destination. Unverified capabilities are not treated as supported.

Package stopped

The local CLI reports service unavailable and does not secretly start the package. Check DSM Package Center and explicitly start the service there if desired.

Corrupt or incompatible index

A corrupt snapshot is not opened as usable. Preserve diagnostics and reset the affected index after confirmation. A new scan rebuilds it without changing source files.
